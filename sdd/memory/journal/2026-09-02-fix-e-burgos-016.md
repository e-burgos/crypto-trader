# FIX-e-burgos-016 — 2026-09-02

## Qué pasó

- `gh secret set HETZNER_API_TOKEN` devolvió `403` con `e-burgos` ya marcada como activa en
  `gh auth status`. El agente concluyó que no tenía permiso, delegó la carga al dev y desplegó a
  mano. El `gh auth switch --user e-burgos` **explícito** —el ritual que `lessons.md` ya exigía—
  lo resolvió al instante: el switch refresca el token del keyring aunque el status diga activa.
- Además el `git push` usó la credencial de `eburgos-flx` mientras `gh` decía `e-burgos`: la cuenta
  de git y la de `gh` no son la misma cosa.

## Lección

- Ante un `403` de `gh`, ejecutar `gh auth switch --user e-burgos` **siempre**, aunque el status ya
  la muestre activa, y volver a la original al terminar. Recién si sigue fallando, delegar.

## Costo evitable

- Un deploy manual completo, dos pushes de diagnóstico y un mensaje al dev pidiendo algo que el
  agente podía hacer.
